# 🤖 arXiv AI 논문 자동 요약 시스템 (Make + Gemini + Notion)

본 프로젝트는 **Make(구 Integromat)**를 허브로 하여 **arXiv**의 최신 AI 연구 데이터를 수집하고, **Gemini AI**로 핵심 내용을 요약하여 **Notion** 데이터베이스에 자동 기록하는 안정적인 데이터 파이프라인입니다.

### ⚙️ 모듈별 입출력 (I/O) 명세
| 단계 | 모듈명 | 입력 데이터 (Input) | 출력 데이터 (Output) |
| :--- | :--- | :--- | :--- |
| **1** | **RSS (arXiv)** | `cs.AI` 카테고리 피드 URL | 제목, 초록(Abstract), URL, 발행일 |
| **2** | **Notion (Search)** | 수집된 논문의 `URL` | 기존 DB 내 동일 URL 존재 여부 (Bundle 수) |
| **3** | **Filter** | Search 결과 Bundle 수 | `Total bundles = 0`일 때만 통과 (중복 방지) |
| **4** | **Gemini AI** | 논문 제목 + 초록 텍스트 | 한국어 3줄 요약 텍스트 |
| **5** | **Notion (Create)** | 요약문, 제목, URL, 날짜 | 노션 데이터베이스 신규 레코드 생성 |

## 2. 기술적 구현 및 운영 정책

### 📡 데이터 수집 및 스케줄링 (재현성 및 기술 원리)
- **수집 방식:** Make의 RSS 모듈을 통한 **HTTP Polling** 방식. XML 데이터를 파싱하여 개별 아이템으로 분리합니다.
- **스케줄링:** 매일 **08:00 (Asia/Seoul)**에 자동 실행되도록 Make 내부 스케줄러(Cron 방식)를 설정했습니다.

### 🔍 중복 방지 전략 (Duplicate Key)
- **중복 키 선정:** 논문의 고유 식별자인 `원문 URL`을 기준으로 검색합니다.
- **의사결정 근거:** GUID나 해시(Hash) 생성 방식보다 arXiv의 Perma-link(고유 URL)를 사용하는 것이 데이터 추적 및 디버깅 측면에서 가장 직관적이고 확실한 중복 방지책이라고 판단했습니다.

### 🛡 에러 처리 및 알림 정책
- **재시도(Retry):** API 일시 오류 발생 시 **5분 간격으로 최대 2회** 자동 재시도합니다.
- **실패 시 정책:** 2회 재시도 후에도 실패할 경우 해당 아이템은 **Skip** 처리하여 전체 파이프라인의 중단을 방지합니다.
- **알림:** 최종 실패 건은 Make의 내장 에러 리포팅 시스템을 통해 관리자 이메일로 통보됩니다.
